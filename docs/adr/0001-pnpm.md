# 1. pnpm replaces Yarn as the package manager

Status: accepted

Date: 2026-08-20

## Context

The repository was built with Yarn. In the weeks before this decision, dependency maintenance was almost entirely Dependabot traffic: PR #39 and PR #40, both merged on 2026-08-17, were `dependabot/npm_and_yarn` branches bumping transitive packages. Each arrived with a lockfile edit that had to be reviewed and re-resolved by hand, and the lockfile gave no direct way to pin a transitive package that the direct dependencies were still asking for at a vulnerable range.

At the same time the repository was growing two harnesses beside the extension. `smoke/` and `ui-test/` each need their own dependency tree, because the extension must not carry a test driver into its VSIX.

## Decision

Migrate the whole repository from Yarn to pnpm, in PR #42, merged 2026-08-20. `packageManager` is set to `pnpm@11.22.0` in the root `package.json` and in both harness manifests, so every install resolves the same way.

The root and `ui-test/` each carry a `pnpm-workspace.yaml` with an `allowBuilds` map that denies postinstall scripts to `@vscode/vsce-sign` and `keytar`, and an `overrides` map pinning `serialize-javascript`, `qs` and `diff` past their advisories. `smoke/` carries a `pnpm-workspace.yaml` too, but it needs neither map and holds only `packages: []`.

## Consequences

A transitive advisory is now closed by one line in `overrides`, without waiting for the direct dependency to move. Commit 2c066cd, "Clear the dependency advisories", used exactly that to take mocha from 10 to 11 and pin the three packages above.

Each harness is installed from its own directory with its own lockfile, and CI caches them separately by `cache-dependency-path`. The cost is three lockfiles and three `pnpm-workspace.yaml` files to keep in step, and an `overrides` block that has to be revisited whenever a direct dependency finally catches up.

Packaging had to change with the manager: `vsce package` runs with `--no-dependencies`, because every dependency is a devDependency and vsce cannot read pnpm's non-hoisted `node_modules` layout.
